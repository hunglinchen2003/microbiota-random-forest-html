資料怎麼拆

原始檔是 otu_table.csv、taxonomy.csv、metadata.csv。三張表先對齊共同的 OTU 與樣本，建成一個 phyloseq 物件，並去掉全為 0 的 OTU 與樣本。

01無法鑑定、ambiguous、uncultured、metagenome、unknown、incertae sedis，或空白的名稱，只在目前這個階層改成 NA。它們不會被併成一個假菌種。
02tax_glom(rank, NArm = TRUE) 把同一個階層名稱的 OTU 讀數加總。門、綱、目、科、屬、種各做一次，互不混用。
03每個樣本換成相對豐度百分比。分母是該階層全部菌的讀數，包含沒有被選進模型的菌。

拉桿無法一次操作幾百個屬。因此模型本身也只用同一批菌：先試盛行率 20%、10%、5%，留下變異數大於 0 的菌；若仍超過 12 個，只留相對豐度變異數最高的 12 個。Domain 幾乎全是 Bacteria，所以沒有單獨建模。

R 如何變成這頁

網頁沒有重新訓練模型，也沒有呼叫 R。訓練仍在 R 完成，export_model.R 把 randomForest 的每一棵樹抄出來，predict.js 只負責走樹與投票。

訓練set.seed(123) 之後立刻 train(Group ~ ., method = "rf")，10-fold CV，ntree = 500。caret 會在全部樣本上，用選中的 mtry 再配一次最終模型。
匯出getTree() 的分裂點以 little-endian IEEE-754 的 base64 儲存。瀏覽器用 DataView.getFloat64 還原同一組位元，<= 才不會因十進位捨入走錯邊。
核對同一份 predict.js 在 R 的 V8 裡執行，整數票數必須與 predict(type = "vote", norm.votes = FALSE) 完全相同。

R

node <- 1L
while (splitVar[node] != 0L) {
  if (x[splitVar[node]] <= split[node]) {
    node <- left[node]
  } else {
    node <- right[node]
  }
}
vote[class[node]] <- vote[class[node]] + 1L

JavaScript

node = 0
while (V[node] !== 0) {
  if (x[V[node] - 1] <= S[node]) node = L[node]
  else node = R[node]
}
votes[C[node] - 1] += 1

R 的節點從 1 起算，葉子的子節點是 0。匯出時改成從 0 起算，終端記成 -1。分裂變數同樣從 1 改成 0。內部節點的 prediction 是 0，只有葉子的類別編號是 1 或 2，程式只檢查葉子。

分類時 randomForest 選的是 票數比例 / cutoff 最大的類別。這個模型的 cutoff 是每個類別 1/2，所以比較的就是整數票數。兩邊票數完全相同時，R 用 unif_rand() 隨機挑一個；這頁不抽該亂數，會標成平手並列出所有領先類別。
